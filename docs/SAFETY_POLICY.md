# 리커버핏 Coach — 안전 정책 (SAFETY POLICY)

> 문서 버전: v0.1 (초안)
> 최종 수정: 2026-09-02
> **이 문서는 제품의 다른 모든 요구사항보다 우선한다.**
> 기능 요구와 충돌하면 항상 이 문서가 이긴다.

---

## 0. 이 문서를 왜 먼저 쓰는가

이 앱은 **아픈 사람이 쓰는 앱**이다. 잘못 만들면 사용자가 다친다.
그래서 화면·기능보다 먼저 "무엇을 하지 않을 것인가"를 확정한다.

이 문서는 개발 중 판단이 갈릴 때의 **결정 기준**이다.
"이 정도는 괜찮지 않을까"라는 판단이 들면, 그 순간이 이 문서를 다시 읽어야 할 때다.

## 1. 제품 정체성 선언

**리커버핏 Coach는 의료기기가 아니며, 의료행위를 하지 않는다.**

| 항목 | 입장 |
|---|---|
| 진단 | 하지 않는다. 병명·원인을 추정해 제시하지 않는다. |
| 치료 | 하지 않는다. "치료", "완치", "낫게 해드립니다" 표현 금지. |
| 처방 | 하지 않는다. 사용자 화면에서 "처방" 단어를 쓰지 않는다. |
| 응급 대응 | 하지 않는다. 응급 상황은 119 및 의료기관 안내로 넘긴다. |
| 약물·보충제 | 권장하지 않는다. 제품·브랜드 언급 금지. |
| 제공하는 것 | 일반적인 **운동 추천**, **회복 루틴**, **영양 가이드**, **기록 도구** |

### 1.1 사용자 화면 표현 규칙 (강제)

| ❌ 금지 표현 | ✅ 대체 표현 |
|---|---|
| 처방 / 운동 처방 | 운동 추천 / 회복 루틴 |
| 치료 / 완치 / 낫습니다 | 회복에 도움 / 관리 |
| 진단 / 진단 결과 | 설문 결과 / 현재 상태 요약 |
| ○○증입니다 / ○○일 가능성이 높습니다 | (병명 언급 자체 금지) |
| 교정해 드립니다 | 자세 개선에 도움이 되는 운동 |
| 통증이 사라집니다 | 통증 완화에 도움이 될 수 있습니다 |
| 식단 처방 / 다이어트 플랜 | 영양 가이드 / 식사 균형 가이드 |
| 안전합니다 (단정) | 무리하지 않는 범위에서 |

> 이 표는 코드 리뷰 체크 항목이다. UI 문구 PR 은 이 표 대조 후 머지한다.

## 2. 3단계 안전 게이트

```
        ┌──────────────────────────────────────────┐
게이트 A │ 설문 진입 시점 — 레드 플래그 스크리닝     │ → 해당 시 즉시 차단
        └──────────────────────────────────────────┘
                          ↓ 통과
        ┌──────────────────────────────────────────┐
게이트 B │ 루틴 생성 시점 — 통증 강도·기간 판정      │ → 차단 또는 Phase 1 강제
        └──────────────────────────────────────────┘
                          ↓ 통과
        ┌──────────────────────────────────────────┐
게이트 C │ 운동 중 / 운동 후 — 중단 사유·통증 변화   │ → 하향 또는 차단
        └──────────────────────────────────────────┘
```

**게이트 원칙**
1. 게이트는 **점수화하지 않는다.** 하나라도 걸리면 걸린 것이다.
2. 게이트 통과 실패 시 **대체 루틴을 제공하지 않는다.** (우회 금지)
3. 게이트 로직은 UI가 아니라 `src/engine/safety/` 에 있고, **단위 테스트가 반드시 존재한다.**
4. 게이트를 끄는 설정·디버그 플래그를 릴리즈 빌드에 남기지 않는다.

## 3. 레드 플래그 (게이트 A)

### 3.1 목록 — 하나라도 "예" 이면 루틴 미제공

| ID | 사용자에게 보이는 문항 | 근거 |
|---|---|---|
| `rf_recent_injury` | 최근 다쳐서 붓거나, 모양이 변했거나, 발을 딛기 어려운 곳이 있나요? | 급성 손상·골절 가능성 |
| `rf_night_pain` | 가만히 있을 때나 자는 동안에도 심한 통증이 있나요? | 비기계적 통증 — 운동으로 접근할 영역 아님 |
| `rf_numbness` | 저리거나 감각이 둔하거나, 힘이 빠지는 느낌이 있나요? | 신경학적 증상 |
| `rf_post_op` | 최근 수술을 받았고, 운동해도 된다는 의료진 확인을 받지 않았나요? | 수술 후 프로토콜은 의료진 영역 |
| `rf_systemic` | 원인 모를 열이 나거나, 의도치 않게 체중이 줄었나요? | 전신 질환 신호 |
| `rf_chest` | 운동할 때 가슴이 아프거나, 숨이 심하게 차거나, 어지러운 적이 있었나요? | 심혈관 위험 신호 |
| `rf_pregnancy` | 임신 중이거나 출산 직후인가요? | 별도 전문 지도 영역 |
| `rf_doctor_stop` | 의료진에게 운동을 제한하라는 안내를 받은 적이 있나요? | 의료진 지시 우선 |

> **문항 문구 원칙**: 의학용어를 쓰지 않는다. 중학생이 읽고 이해할 수 있어야 한다.
> **위 목록은 초안이다.** 최종 확정 전 건강운동관리사·물리치료사·의료 전문가 검수를 받는다.

### 3.2 응급 즉시 안내 (별도 취급)
`rf_chest` 항목에 "예" 이면, 다른 차단 안내보다 **먼저** 응급 안내를 보여준다.
> "운동 중 가슴 통증, 심한 호흡곤란, 어지럼은 즉시 확인이 필요한 신호입니다.
> 지금 증상이 있다면 119에 연락하거나 가까운 의료기관을 방문하세요."

## 4. 통증 게이트 (게이트 B)

### 4.1 통증 척도
0~10 숫자 슬라이더 + **한국어 라벨 병기** (숫자만 두면 사용자마다 기준이 다르다).

| 값 | 라벨 |
|---|---|
| 0 | 통증 없음 |
| 1-3 | 신경 쓰이지만 일상생활 가능 |
| 4-6 | 움직일 때 꽤 아픔, 동작이 제한됨 |
| 7-8 | 많이 아픔, 일상생활이 어려움 |
| 9-10 | 참기 어려움 |

### 4.2 판정 (초안값 — 검수 필요)
| 최고 통증 | 처리 |
|---|---|
| 7 이상 | **루틴 미제공 → 상담 안내** |
| 4~6 | Phase 1 강제 (통증 완화 / 가동성만) |
| 1~3 | Phase 2 이하 |
| 0 | 목표에 따라 Phase 결정 |

**추가 차단 조건 (통증 강도와 무관)**
- 지속 기간 `over3m` (3개월 이상) + 통증 4 이상 → 차단 후 상담 안내 (만성 통증은 전문 평가 영역)
- 같은 부위 통증 증가가 3회 연속 기록됨 → 차단

> 컷오프 숫자 7 / 4 / 3개월 / 3회는 **모두 설계 초안값**이다.
> 임상 근거로 확정된 값이 아니며, 전문가 검수 전에는 확정 수치로 표기·홍보하지 않는다.

## 5. 운동 중 / 운동 후 안전 (게이트 C)

### 5.1 실행 화면 상시 노출
- 화면 하단 고정: **[운동 중단]** 버튼 — 항상 한 번의 탭으로 닿아야 한다.
- 각 동작 카드에 `stopSigns`(즉시 중단 신호) 를 접힘 없이 노출한다.

### 5.2 즉시 중단 신호 (모든 동작 공통)
> - 날카롭거나 찌르는 통증이 생길 때
> - 저림이나 힘 빠짐이 생길 때
> - 어지럽거나 숨이 심하게 찰 때
> - 통증이 운동 전보다 뚜렷하게 심해질 때
>
> → 중단하고, 증상이 계속되면 전문가와 상담하세요.

### 5.3 중단 후 처리
| 중단 사유 | 처리 |
|---|---|
| 통증 (`pain`) | 즉시 세션 종료. 다음 루틴 강도 하향. 2회 반복 시 상담 안내 |
| 난이도 (`difficulty`) | 강도 하향 제안 |
| 시간 (`time`) | 기록만, 강도 유지 |
| 기타 | 기록만 |

### 5.4 운동 후 체크 (필수 단계 — 건너뛸 수 없음)
1. 지금 통증은 운동 전과 비교해 어떤가요? (줄었다 / 비슷하다 / 심해졌다)
2. 오늘 루틴은 어땠나요? (1~5)

"심해졌다" 연속 2회 → Phase 한 단계 하향 + 안내.
"심해졌다" 연속 3회 → **루틴 제공 중단 + 상담 안내.**

## 6. 학생 사용자 보호 정책

> 대상: 만 18세 미만 또는 사용자가 "학생 모드"를 선택한 경우.
> 만 18세 미만은 **일반 모드로 전환할 수 없다.**

### 6.1 절대 제공하지 않는 것
| 금지 | 사유 |
|---|---|
| 목표 체중 입력·설정 기능 | 감량 목표 고착 → 섭식장애 위험 |
| 감량 기한 설정 | 급속 감량 유도 |
| 칼로리 숫자 목표 제시 | 성장기 에너지 제한 위험 |
| 체지방률 목표 | 신체 이미지 압박 |
| BMI 판정 문구 ("과체중입니다" 등) | 낙인·자기평가 왜곡 |
| 단식·원푸드·디톡스·클렌즈 콘텐츠 | 근거 없음 + 위험 |
| 특정 식품 "금지" 목록 | 흑백 사고 유발 |
| 체중 변화 그래프 | 숫자 집착 강화 |
| 다른 사용자와의 비교·랭킹 | 경쟁 압박 |

### 6.2 학생 모드 표현 규칙
| 상황 | 표현 |
|---|---|
| 영양 목표 선택지 | "체중 감량" 대신 **"건강한 성장과 컨디션 관리"** |
| 섭취량 안내 | 그램·칼로리 대신 **손바닥 / 주먹 / 엄지 기준** |
| 식사 조언 | "줄이세요" 대신 **"함께 챙기세요"** (제한이 아니라 추가 프레임) |
| 체중 언급 | 결과 화면에서 "체중", "감량", "칼로리" 단어를 노출하지 않는다 |

### 6.3 체중 관련 문의가 감지될 때 (선택지 등)
> "체중 관리는 성장 시기와 개인 상태에 따라 달라서, 앱이 개별 목표를 정해드리지 않아요.
> 학교 보건 선생님, 보호자, 또는 영양·의료 전문가와 함께 상의하는 것이 가장 안전합니다."

### 6.4 학생 모드 UI 강제 규칙 (구현 레벨)
- `NutritionGuide.calorieRange` 와 `macroRatio` 는 학생 모드에서 **엔진 단계에서 `undefined`** 로 반환한다.
  (UI에서 숨기는 방식 금지 — 데이터 자체를 만들지 않는다.)
- 이 규칙은 단위 테스트로 고정한다.

## 7. 차단 화면(blocked) 설계 규칙

### 7.1 반드시 포함
1. **왜 루틴을 드리지 못하는지** — 사유 유형만 (병명 추정 금지)
2. **어디에 상담해야 하는지**
   - 성인: 정형외과 / 재활의학과 / 스포츠의학과, 물리치료사, 건강운동관리사
   - 학생: 학교 보건교사, 보호자, 그리고 위 의료기관
3. **응급 상황 안내**: 가슴 통증·심한 호흡곤란·의식 저하 → 119
4. **재진입 경로**: "상태가 나아지면 설문을 다시 진행할 수 있어요"

### 7.2 반드시 제외
- 대체 운동, "가벼운 스트레칭이라도" 같은 완화 제안
- 원인 설명, 병명 추정, 회복 기간 예측
- "괜찮을 거예요" 같은 안심 표현 (근거 없는 안심은 위험)

### 7.3 차단 화면 문구 (초안)
> **지금은 운동 루틴을 안내해 드리지 않는 게 좋겠어요.**
>
> 응답해 주신 내용 중에, 앱의 일반적인 운동 추천만으로는 판단하기 어려운 항목이 있었습니다.
> 이런 경우에는 직접 몸 상태를 확인해 줄 수 있는 전문가의 도움을 받는 것이 가장 안전합니다.
>
> · 정형외과 / 재활의학과 진료
> · 학교 보건 선생님이나 보호자와 상의 *(학생 모드)*
>
> **바로 도움이 필요한 경우** — 가슴 통증, 심한 호흡곤란, 의식이 흐려지는 느낌이 있다면 즉시 119에 연락하세요.
>
> 상태가 나아지면 언제든 설문을 다시 진행하실 수 있어요.

## 9. 개인정보 / 건강정보 보호

### 9.1 원칙
1. 건강정보(설문 응답, 통증 기록)는 **기기 밖으로 나가지 않는다.**
2. MVP에는 애널리틱스·크래시 리포팅·광고 SDK를 넣지 않는다.
3. 이름·연락처·학번·소속 학교를 **입력받지 않는다.** (입력란 자체를 만들지 않는다)
4. 자유 텍스트 입력을 최소화한다 — 자유 입력은 예측 못 한 개인정보가 들어온다.
5. 로그에 설문 응답을 출력하지 않는다. 개발 중 디버그 로그도 릴리즈 전 제거.
6. GitHub 저장소, 이슈, 스크린샷, 문서에 **실제 사용자 데이터를 올리지 않는다.**
7. `.env`, 키스토어, 인증서는 커밋하지 않는다.

### 9.2 사용자 권리
- 설정에서 **전체 데이터 삭제** 가능 (2단계 확인 후 즉시 완전 삭제).
- 삭제 후에는 복구할 수 없음을 명시한다.

### 9.3 향후 서버 도입 시 (지금은 하지 않음)
서버 저장·클라우드 백업·계정 기능을 도입하려면 아래를 **먼저** 끝낸다.
- [ ] 개인정보 처리방침 전면 작성 (건강정보는 민감정보로 취급)
- [ ] 별도 동의 절차 설계 (포괄 동의 금지)
- [ ] 만 14세 미만 법정대리인 동의 처리 방안
- [ ] 저장·전송 암호화, 접근 통제, 보관 기간·파기 절차
- [ ] 법률 검토

## 10. 콘텐츠 안전 규칙 (운동)

1. 통증을 참고 수행하도록 유도하는 표현 금지. ("아파도 참고", "한계까지" 등)
2. 고위험 동작은 MVP 콘텐츠에서 제외한다.
   - 예: 무거운 중량 하중 동작, 폭발적 점프·플라이오메트릭(초기 Phase), 목 과신전·급격한 회전, 척추 굴곡 하 중량 부하
3. 각 동작에는 **반드시** `cautions`(주의)와 `stopSigns`(중단 신호)를 채운다. 비어 있으면 콘텐츠 미완성으로 간주.
4. Phase 를 건너뛰는 경로를 만들지 않는다.
5. 동작 설명은 **한 문장에 한 지시**. 복합 지시는 부상 위험을 높인다.
6. 시간·횟수는 상한을 두고, "더 하고 싶으면 더 하세요" 같은 개방형 문구를 쓰지 않는다.

## 15. 설문 건너뛰기와 안전 게이트 (v0.2 추가)

사용자가 설문을 전부 답하지 않고도 앱을 쓸 수 있게 하되, 안전 게이트는 그대로 둔다.

### 15.1 건너뛸 수 있는 것 / 없는 것

| 구분 | 항목 |
|---|---|
| **건너뛸 수 없음** | 안전 안내 동의, 사용자 유형, 나이대, **위험 신호 12개**, 통증 부위를 골랐다면 그 통증 점수 |

- 위험 신호는 빠른 시작에서도 12개 전부 확인한다. 화면에 건너뛰기 버튼을 두지 않는다.

### 15.2 건너뛴 항목의 기본값
가장 부담이 적은 쪽으로 채운다.

| 항목 | 기본값 | 이유 |
|---|---|---|
| 목표 | 일반 건강관리 | 강도가 가장 낮은 경로 |
| 가능 시간 | 20분 | 중간값 |
| 운동 경험 | 없음 | 초급 운동만 배정되도록 |
| 성별 | 응답하지 않음 | 필수 정보가 아님 |
| 수면·스트레스 | 보통 | 추가 주의 문구를 만들지 않음 |

### 15.3 테스트로 고정한 것
- `SKIPPABLE` 목록에 `redFlags`, `painDetail`, `userType`, `basic` 이 들어가면 테스트 실패
- 빠른 시작 경로에도 `redFlags` 단계가 반드시 포함되는지 소스 검사

## 17. 개인정보 동의와 체중 입력 (v0.3 추가)

### 17.1 왜 넣었나
체중 1kg 당 단백질 목표를 계산하려면 체중이 필요하다.
성인과 학생을 다른 모드로 나누는 대신, **앱을 처음 켤 때 개인정보 수집·이용 동의를 받고
체중은 선택 입력으로 두는** 방식을 택했다. (2026-09-02 결정)

### 17.2 동의 순서
```
온보딩 → 안전 안내 동의 → 개인정보 동의 → 설문
```
- 두 동의를 모두 마치기 전에는 온보딩 밖으로 나갈 수 없다. (`routeGuard.isRouteAllowed`)
- 동의 버전은 `DISCLAIMER_VERSION`, `PRIVACY_VERSION` 으로 각각 관리한다.
- 개인정보 안내문(`src/utils/privacy.ts`)은 **법률 검토를 받지 않았다.** 배포 전 검토가 필요하다.

### 17.3 체중 입력 규칙
1. **선택 입력이다.** 넣지 않아도 설문이 끝나고 루틴이 나온다.
2. 숫자 키보드를 주지 않고 **5kg 단위 버튼**으로 고른다.
   정확한 숫자를 떠올리며 체중에 몰두하지 않게 하기 위해서다.
3. 체중을 넣지 않으면 하루 단백질 g 수를 계산하지 않고, 손 기준 안내만 보여 준다.
4. 체중을 넣어도 **목표 체중·감량 목표는 만들지 않는다.** 계산에만 쓴다.
5. 단백질 기준값(g/kg)은 `mealTemplates.ts` 의 `proteinPerKg.source` 에 근거를 적고,
   화면에도 그 문장을 그대로 보여 준다. 영양 전문가 검수 전이다.

## 19. 부위별 손상 교육 자료와 운동 지침 (v0.3 추가)

### 19.1 교육 자료 (`src/data/injuryEducation.ts`)
1. **'이런 손상이 있다' 는 설명이다. '당신이 이 손상이다' 라고 말하지 않는다.**
   증상 목록은 `commonPicture`(흔히 이런 이야기를 합니다) 라는 이름으로 두고,
   화면에서도 "증상이 비슷하다고 같은 손상인 것은 아닙니다" 를 함께 보여 준다.
2. **재활 기간을 주·개월 숫자로 적지 않는다.**
   같은 손상도 정도·수술 여부·나이에 따라 다르고, 앱이 날짜를 적으면 사용자가
   그 날짜에 맞춰 복귀하려 한다. 대신 '무엇이 되면 다음 단계' 로 적는다.
   이 규칙은 테스트(`learn.test.ts`)로 고정했다.
3. 치료·수술 설명은 **병원이 하는 일**로만 쓴다. 앱이 그 행위를 한다고 읽히면 안 된다.
4. 그림(`AnatomyDiagram`)은 **개념도**다. 실제 해부도·사진이 아니며 화면에도 그렇게 밝힌다.
   실제 해부 사진과 의학 삽화는 저작권이 있어 앱에 넣지 않는다.
5. 부위마다 **병원부터 가야 하는 신호**를 danger 톤으로 함께 보여 준다.
6. 이 자료는 **의료 전문가 검수 전이다.**

### 19.2 운동 지침 (`src/data/activityGuidelines.ts`)
1. 앱이 만든 숫자가 아니라 **이미 공개된 권고를 옮긴 것**이다.
2. 항목마다 `verified` 와 `source` 를 둔다.
   원문을 확인하지 못한 항목은 `verified: false` 로 두고 화면에 **'확인 필요'** 라고
   그대로 보여 준다. 확인하지 못한 것을 확인한 것처럼 쓰지 않는다.
3. **성인 기준과 청소년 기준을 나눈다.** 학생에게 성인 기준(주 150분)을 그대로
   안내하면 오히려 적게 움직이는 목표가 된다.
4. 통증이 있거나 치료 중인 사람에게 이 숫자를 목표로 주지 않는다.
   그 경우 회복운동 단계가 먼저이고, 담당 전문가의 지시가 항상 우선이다.

## 20. 동의 화면의 '끝까지 읽음' 판정 (v0.3.1 수정)

### 20.1 무엇이 문제였나
안전 안내와 개인정보 동의는 **끝까지 읽어야 동의 버튼이 열립니다.** (§8)
그런데 판정을 스크롤 이벤트로만 하고 있어서, 화면이 커서 안내문이 한눈에
다 들어오는 경우(데스크톱 브라우저, 태블릿) **스크롤이 아예 일어나지 않아
동의 버튼이 영영 잠겼습니다.** 2026-09-03 웹 배포 후 실제로 발생했습니다.

### 20.2 어떻게 고쳤나
`src/utils/useReadToEnd.ts` 로 판정을 옮기고, 기준을 바꿨습니다.

| | 옛 기준 | 새 기준 |
|---|---|---|
| 무엇을 보나 | 스크롤이 바닥에 닿았는가 | **마지막 줄이 화면에 들어왔는가** |
| 짧은 안내문 | 판정 불가 (버튼 잠김) | 통과 |
| 긴 안내문 | 끝까지 내려야 통과 | 끝까지 내려야 통과 (그대로) |
| 높이를 아직 못 잼 | — | 통과시키지 않음 |

**안전 기준을 낮춘 것이 아닙니다.** '안 보여 준 내용을 건너뛰게 하지 않는다' 는
원칙은 그대로이고, 다 보여 준 경우를 못 알아보던 것을 고쳤습니다.

### 20.3 테스트로 고정한 것 (`consentScroll.test.ts`)
- 내용이 화면보다 짧으면 스크롤 없이 통과한다
- 내용이 화면보다 길면 끝까지 내리기 전에는 통과하지 않는다
- 높이를 재기 전에는 통과하지 않는다
- 두 동의 화면이 같은 판정(`useReadToEnd`)을 쓴다
- 두 화면 모두 건너뛰기 성격의 버튼이 없다

## 21. 투트랙 시작 경로 (v0.4)

### 21.1 왜 나눴나
아픈 곳이 없는 사람에게까지 16문항 설문을 요구하니 시작 자체가 부담이었습니다.
"설문이 너무 많다" 는 실제 사용 의견을 받아 2026-09-03 두 갈래로 나눴습니다.

| 트랙 | 무엇으로 정하나 | 길이 |
|---|---|---|
| 목적 트랙 | **운동 목적에 따라 결정** | 5단계 |
| 설문 트랙 | **설문 결과에 따라 결정** | 빠른 시작 6단계 / 자세히 16단계 |

### 21.2 양보하지 않은 세 가지

**1. 목적 트랙에서도 위험 신호 확인을 건너뛰지 않는다.**
다만 묻는 항목이 다릅니다. 12개 중 6개(`PURPOSE_TRACK_FLAG_IDS`)를 묻습니다.

| 목적 트랙에서 묻는 것 | 빼는 것 |
|---|---|
| 가슴 통증·호흡곤란 (응급) | 심한 외상 후 통증 |
| 대소변 이상 (응급) | 골절·탈구 의심 |
| 저림·마비 | 관절 모양 이상 |
| 힘 빠짐 | 체중 부하 불가 |
| 원인 모를 체중 감소 | 심한 붓기·열감 |
| 수술 직후·운동 제한 | 야간통 |

빼는 6개는 **모두 '아픈 부위가 있다' 를 전제로 하는 항목**이라, 아픈 곳이 없다고
답한 사람에게는 물어도 의미가 없습니다. 아픈 곳이 있다고 하면 설문 트랙으로 넘어가
12개를 모두 묻습니다.

⚠️ 이 구분은 앱 제작자가 정한 것이며 **의료 전문가 검수 전**입니다.

**2. 아픈 몸에 목적만 보고 운동을 주지 않는다.**
목적 트랙에서 '아프거나 불편한 곳이 있어요' 를 고르면 목적 선택 화면으로 가지 않고
부위·통증 정도를 묻는 설문 트랙으로 넘어갑니다. `resolveTrack()` 이 판정하며,
화면 흐름과 별개로 **저장 직전에 한 번 더** 바로잡습니다
(`painRegions` 가 비어 있지 않으면 무조건 설문 트랙으로 저장).

**3. 목적 트랙에서는 부위별 회복운동을 제공하지 않는다.**
회복운동은 통증 정도와 단계 판정이 있어야 배정할 수 있습니다.
운동 탭에서 회복 묶음 자체를 감추고, 왜 감췄는지와 어떻게 열 수 있는지 안내합니다.
(`isCategoryAllowed`)

### 21.3 학생 보호는 두 트랙 모두 동일
목적 트랙에서도 사용자 유형과 나이대를 묻습니다. 이 두 값이 없으면 학생 모드가
켜지지 않아 숫자 목표가 그대로 노출되기 때문입니다. (§6)

### 21.4 테스트로 고정한 것 (`tracks.test.ts`)
- 목적으로 시작했어도 아픈 곳이 있으면 설문 트랙으로 넘어간다
- 저장 직전에 한 번 더 바로잡는 코드가 화면에 남아 있다
- 목적 트랙 위험 신호 목록에 응급 신호가 반드시 들어 있다
- 뺀 항목이 '아픈 부위 전제' 6개와 정확히 일치한다
- 어떤 목적도 회복 카테고리를 가리키지 않는다
- 운동 탭이 트랙에 따라 목록을 거른다
- 목적 트랙에서도 나이대를 묻는다 (학생 보호)

## 22. 통증 슬라이더 표시 (v0.4)

0~10 눈금은 **반드시 한 줄**에 둡니다. 칸 너비를 고정하면 좁은 화면에서 '10' 만
다음 줄로 밀려나, 눈금이 9에서 끝나는 것처럼 보이고 **통증이 실제보다 낮아 보이는
착시**가 생깁니다. (2026-09-03 실제 제보)

줄바꿈을 막고(`flexWrap: 'nowrap'`) 칸이 남은 폭을 나눠 갖게(`flex: 1`) 했습니다.
세로 크기는 `MIN_TOUCH_SIZE` 를 지킵니다. `accessibility.test.ts` 로 고정했습니다.

## 23. 운동·프로그램 편집 (v0.5)

### 23.1 왜 넣었나
운동 86개와 프로그램 23개가 코드 안에만 있어, 지도 경험이 있는 선생님이
동작 설명 하나 고치려 해도 개발자를 거쳐야 했습니다. 영상은 앱에서 관리할 수 있게
해 두고 정작 운동 내용은 못 고치게 둔 것은 설계 실수였습니다. (2026-09-03)

### 23.2 무엇을 바꿀 수 있나
- 운동: 이름·목적·동작 순서·코칭 문구·흔한 실수·주의사항·쉬운/어려운 버전
- 운동: 분류·부위·단계·난이도·도구·세트·횟수·유지 시간·휴식
- 운동: 새로 만들기 / 감추기 / 되돌리기
- 프로그램: 이름·설명·대상·목표·소요 시간·주당 횟수·분류·난이도
- 프로그램: **어떤 운동을 어느 순서로 넣을지** (넣기·빼기·순서 바꾸기)
- 프로그램: 중단 기준·주의사항·다음 단계 기준
- 프로그램: 새로 만들기 / 감추기 / 되돌리기

### 23.3 저장이 막히는 경우 (`checkExercise` / `checkProgram`)

| 막는 것 | 이유 |
|---|---|
| 운동의 **주의사항이 빈 경우** | 무엇을 조심해야 하는지 없는 동작은 내보낼 수 없다 |
| 프로그램의 **중단 기준이 빈 경우** | 언제 멈춰야 하는지 모르면 안전 장치가 사라진다 |
| 프로그램의 **주의사항이 빈 경우** | 위와 같다 |
| **통증을 참으라는 표현** | 이 앱의 가장 기본 원칙을 정면으로 어긴다 (§10) |
| 이름·목적·동작 순서가 빈 경우 | 화면이 비어 버린다 |
| 프로그램에 운동이 하나도 없는 경우 | 루틴이 비어 버린다 |
| **목록에 없는 운동을 가리키는 프로그램** | 루틴이 조용히 비어 버린다 |

막는 표현: `참고 하`, `참고 계속`, `참으세요`, `참으면서`, `아파도 계속`,
`아파도 하`, `버티세요`, `한계까지`, `통증을 이겨`

### 23.4 막지 않고 알리는 경우
`처방`, `완치`, `진단`, `치료해`, `치료합니다`, `낫게 합니다` 가 들어가면
저장은 되지만 화면에 경고를 띄웁니다. **'물리치료사와 상의하세요' 처럼 정당하게
쓰는 경우가 있어** 일률적으로 막지 않습니다.

부위나 단계를 바꾸면 `PHASE_CHANGE_WARNING` 을 크게 보여 줍니다.
1단계 운동을 3단계로 옮기면 통증이 남아 있는 사람에게 부담이 큰 동작이 갈 수 있습니다.

### 23.5 지우지 않고 감춘다
기본 운동·프로그램은 **지우지 않고 감춥니다.** 되돌릴 수 있어야 하기 때문입니다.
사용자가 직접 만든 것만 완전히 지웁니다.

### 23.6 고친 내용이 앱 전체에 반영된다
상세 화면에는 고친 설명이 보이는데 운동 중 화면에는 원래 설명이 나오는 엇갈림을
막기 위해, 조회 함수(`getExercise` · `getProgram`)가 편집 내용을 함께 봅니다.
(`src/data/libraryOverrides.ts`) 앱이 시작될 때 `SafetyGate` 가 편집 내용을 먼저
읽어 두므로, 새로고침 직후에도 고친 내용이 나옵니다.

### 23.7 저장 위치
`@rfc/libraryOverrides` 에 이 기기 안에만 저장됩니다.
**'내 데이터 전체 삭제' 대상이 아닙니다.** 건강 정보가 아니라 선생님이 만든 자료이기
때문입니다. 되돌리기는 편집 화면에서 따로 합니다.
오래 남기려면 '코드로 내보내기' 로 뽑아 `src/data/` 에 붙여 넣습니다.

### 23.8 테스트로 고정한 것 (`library.test.ts`)
- 주의사항·중단 기준을 비우면 저장되지 않는다
- 통증을 참으라는 표현은 저장 자체가 막힌다
- 의료 표현은 막지 않고 경고만 한다
- 기본 운동은 감춰지고 되돌릴 수 있다
- 목록에 없는(또는 감춘) 운동을 가리키는 프로그램은 저장되지 않는다
- 기본 데이터 자체는 편집으로 바뀌지 않는다
- 편집 내용은 '내 데이터 전체 삭제' 대상이 아니다
