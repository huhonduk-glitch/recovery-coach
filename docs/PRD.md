# 리커버핏 Coach — 제품 요구사항 정의서 (PRD)

> 문서 버전: v0.1 (초안)
> 최종 수정: 2026-09-02
> 상태: 검토 대기 — 의료/운동 전문가 감수 전

---

## 1. 제품 개요

**리커버핏 Coach**는 사용자가 간단한 설문에 답하면, 현재 몸 상태에 맞는 **운동 추천**, **회복 루틴**, **영양 가이드**를 받아 혼자서도 안전하게 운동할 수 있도록 돕는 모바일 앱이다.

- 앱 이름(가칭): 리커버핏 Coach (RecoverFit Coach)
- 저장소명: `recovery-coach`
- 플랫폼: iOS / Android (Expo React Native)
- 언어: 한국어 (기본), 다국어 확장 여지 남김
- 1차 버전 구조: **서버 없음 / 전면 로컬 저장**

### 1.1 한 줄 정의
"학교 체육교사가 옆에서 코칭해주는 느낌으로, 아픈 부위와 몸 상태에 맞는 회복 운동과 균형 잡힌 식사 가이드를 안내하는 앱."

---

## 2. 앱 목표

### 2.1 제품 목표
1. 사용자가 **5분 이내 설문**으로 자신에게 맞는 회복 루틴을 받는다.
2. 사용자가 **영상·전문가 없이 앱 화면만 보고** 동작을 따라 할 수 있다.
3. 위험 신호가 있는 사용자는 **운동을 받지 않고 전문가 상담으로 안내**된다.
4. 학생 사용자가 **체중·칼로리 숫자에 매몰되지 않고** 균형식 개념을 익힌다.
5. 사용자가 **자신의 통증·컨디션 변화를 기록**하고 추이를 확인한다.

### 2.2 비목표 (Non-goals) — 명시적으로 하지 않는 것
| 하지 않는 것 | 이유 |
|---|---|
| 의학적 진단·병명 판정 | 의료행위. 앱 범위 밖 |
| 치료·완치 주장 | 의료법·표시광고 위반 소지 |
| 의료 처방(약물·물리치료 처방) | 의료행위 |
| 개인별 칼로리 목표치 강제 제시 | 성장기 청소년 섭식 위험 |
| AI 생성 운동 처방 | 안전성 검증 불가. 룰 기반만 사용 |
| 사용자 건강정보 서버 전송 | 1차 버전은 로컬 저장 원칙 |
| 체중 감량 목표치·기한 설정 기능 | 극단적 감량 유도 위험 |

### 2.3 용어 원칙 (사용자 화면 노출 문구)
| 사용 금지 | 사용 권장 |
|---|---|
| 처방, 처방전 | 운동 추천, 회복 루틴 |
| 치료, 완치, 교정해드립니다 | 회복 도움, 관리, 개선에 도움 |
| 진단 결과 | 설문 결과, 현재 상태 요약 |
| 식단 처방, 다이어트 플랜 | 영양 가이드, 식사 균형 가이드 |
| 통증 없앰 | 통증 완화에 도움 |

## 3. 사용자 페르소나

### P1. 고등학생 — "무릎이 아픈 체대 입시생" (17세, 여)
- 상황: 방과 후 훈련 중 무릎 앞쪽 통증. 병원 갈 시간이 없다고 느낌.
- 니즈: 지금 훈련을 해도 되는지, 무엇을 하면 안 되는지 알고 싶음.
- 리스크: 통증을 참고 훈련을 강행할 가능성. 체중 조절 압박.
- 앱 대응: **학생 모드** 기본 적용. 칼로리 숫자 미노출. 통증 강도 높으면 루틴 미제공 후 상담 안내.

### P2. 일반 성인 — "앉아서 일하는 직장인" (34세, 남)
- 상황: 목·어깨 뻐근함, 허리 뻣뻣함. 헬스장은 다니지만 뭘 해야 할지 모름.
- 니즈: 짧고 정확한 회복 루틴, 자세 교정.
- 앱 대응: 체형교정 + 목/등 상부 회복 루틴, 데스크 5분 루틴.

### P3. 운동 지도자 — "체육교사 / 트레이너" (41세)
- 상황: 학생·회원에게 회복 운동을 설명해야 함. 근거와 단계 구조가 필요.
- 니즈: 부위별 4단계 진행 구조, 학생에게 보여줄 수 있는 화면.
- 앱 대응: 루틴 상세 화면, 단계별 진행 기준, 지도 참고 노트(확장 기능).

### P4. 재활 초기 사용자 — "수술·부상 후 회복기" (52세, 여)
- 상황: 병원 치료는 끝났고, 집에서 뭘 해야 할지 모름.
- 니즈: 아주 낮은 강도부터 시작하는 단계.
- 앱 대응: Phase 1부터 강제 시작. 의료진 지시 우선 안내 문구 상시 노출.

## 4. 주요 사용자 흐름

### 4.1 최초 실행 흐름 (Onboarding → 첫 루틴)
```
[앱 실행]
  ↓
① 온보딩 (3~4장 슬라이드: 앱이 하는 일 / 하지 않는 일)
  ↓
② 안전 안내 및 동의 (의료 면책 + 데이터 로컬저장 안내 + 동의 체크)
  ↓  동의 거부 → 앱 이용 불가 안내 화면 (재동의 유도)
③ 사용자 기본 정보 (연령대, 성별, 학생/일반 모드 선택)
  ↓
④ 안전 스크리닝 설문 (레드 플래그 문항)
  ├─ 레드 플래그 감지 → [전문가 상담 안내 화면] → 루틴 미제공 (종료)
  └─ 통과
      ↓
⑤ 본 설문 (부위 / 통증 / 활동수준 / 목표 / 영양)
  ↓
⑥ 결과 요약 화면 (현재 상태 요약 + 주의사항)
  ├─ [운동 추천 결과] → 루틴 실행 화면
  └─ [영양 가이드 결과]
  ↓
⑦ 기록 저장 (로컬)
```

### 4.2 재방문 흐름
```
[홈] → 오늘의 루틴 → 실행 → 운동 후 통증 체크(0~10) → 기록 저장
                                   ↓
                          통증 악화 감지 → 강도 하향 또는 상담 안내
```

### 4.3 위험 신호 발생 흐름 (모든 화면에서 진입 가능)
```
설문 중 / 운동 중 / 운동 후 통증 체크
  → 레드 플래그 조건 충족
  → [즉시 루틴 중단] → [상담 안내 화면]
  → 안내: 정형외과·재활의학과 / 스포츠 손상 전문의 / 학교 보건교사
  → 기록에 "상담 권고" 플래그 저장 (사유는 저장하되 진단명은 저장하지 않음)
```

## 5. 화면 구조

### 5.1 전체 화면 맵
```
app/
├─ (onboarding)
│   ├─ intro            온보딩 슬라이드
│   ├─ safety           안전 안내 및 동의
│   └─ profile          기본 정보 입력
├─ (survey)
│   ├─ screening        안전 스크리닝(레드 플래그)
│   ├─ body             부위 선택 (신체 지도)
│   ├─ pain             통증/증상 상세
│   ├─ activity         활동 수준·운동 경험
│   ├─ goal             목표 선택
│   └─ nutrition        영양 설문
├─ (result)
│   ├─ summary          결과 요약
│   ├─ exercise         운동 추천 결과
│   ├─ nutrition        영양 추천 결과
│   └─ blocked          상담 안내 (루틴 미제공)
├─ (tabs)
│   ├─ home             홈 / 오늘의 루틴
│   ├─ routine          루틴 목록·카테고리
│   ├─ record           기록
│   └─ settings         설정
└─ session
    ├─ [routineId]      루틴 개요
    ├─ play             운동 실행 (타이머/세트)
    └─ complete         운동 후 체크 + 저장
```

### 5.2 화면별 핵심 요구사항

| # | 화면 | 핵심 요소 | 완료 조건 |
|---|---|---|---|
| 1 | 온보딩 | 3~4장, "이 앱이 하지 않는 것" 슬라이드 필수 | 건너뛰기 가능, 설정에서 재열람 |
| 2 | 안전 동의 | 면책 전문, 스크롤 끝까지 내려야 동의 활성화 | 동의 시각 로컬 저장 |
| 3 | 기본 정보 | 연령대(선택지), 성별(선택/미입력 가능), 모드(학생/일반) | 만 18세 미만 → 학생 모드 자동 |
| 4 | 안전 스크리닝 | 레드 플래그 문항 (예/아니오) | 1개라도 예 → blocked 화면 |
| 5 | 부위 선택 | 신체 지도(앞/뒤) 탭 선택, 다중 선택 최대 3부위 | 미선택 시 "통증 없음/예방" 경로 |
| 6 | 통증 상세 | 통증 강도(0~10 슬라이더), 지속 기간, 악화 동작 | 부위별 반복 |
| 7 | 활동 수준 | 주당 운동 빈도, 운동 경험, 가용 시간 | — |
| 8 | 목표 | 회복 / 체형교정 / 기능 향상 / 체중관리 / 근육량 | 다중 선택 최대 2 |
| 9 | 영양 설문 | 식사 규칙성, 단백질 섭취 빈도, 알레르기·제한 | 학생 모드는 문항 축소 |
| 10 | 결과 요약 | 상태 요약 문장 + 추천 카테고리 + 주의사항 카드 | — |
| 11 | 운동 추천 결과 | 추천 루틴 카드 목록, 현재 Phase 표시 | 시작 버튼 |
| 12 | 루틴 실행 | 동작명·이미지·큐·횟수/시간, 타이머, 다음/이전, 중단 | 중단 시 사유 선택 |
| 13 | 운동 후 체크 | 통증 변화(감소/유지/증가), 체감 난이도 | 증가 → 강도 하향 안내 |
| 14 | 영양 결과 | 목표별 가이드, 손바닥/주먹 기준 시각 카드 | 학생 모드 칼로리 숨김 |
| 15 | 기록 | 날짜별 수행 이력, 통증 추이 그래프 | 로컬 데이터만 |
| 16 | 설정 | 모드 전환, 알림, 데이터 삭제, 면책 재열람, 문의 | 전체 삭제 = 완전 삭제 |

## 6. 설문 문항 구조

### 6.1 설문 4단 구성
```
STAGE 0  기본 정보        → 모드 결정
STAGE 1  안전 스크리닝     → 통과/차단 결정   ← 여기서 막히면 이후 진행 없음
STAGE 2  운동 설문        → 운동 추천 입력값
STAGE 3  영양 설문        → 영양 가이드 입력값
```

### 6.2 STAGE 0 — 기본 정보
| ID | 문항 | 타입 | 선택지 |
|---|---|---|---|
| `age_band` | 연령대 | single | 13-15 / 16-18 / 19-29 / 30-39 / 40-49 / 50-59 / 60+ |
| `sex` | 성별 | single | 여 / 남 / 응답 안 함 |
| `mode` | 이용 모드 | single | 학생 / 일반 (18세 미만은 학생 고정) |
| `height_weight` | 키·체중 | optional | **선택 입력. 학생 모드는 문항 자체를 노출하지 않음** |

### 6.3 STAGE 1 — 안전 스크리닝 (레드 플래그)
> 모두 예/아니오. **1개라도 "예" → 운동 루틴 미제공 → 상담 안내**
> 실제 문항은 SAFETY_POLICY.md 의 레드 플래그 목록과 1:1 대응한다.

| ID | 문항 요지 |
|---|---|
| `rf_recent_injury` | 최근 급성 부상(부기·변형·체중 지지 불가)이 있나요? |
| `rf_night_pain` | 쉬고 있을 때나 밤에도 심한 통증이 있나요? |
| `rf_numbness` | 저림·감각 저하·힘 빠짐이 있나요? |
| `rf_post_op` | 최근 수술을 받았고 의료진의 운동 허가를 받지 않았나요? |
| `rf_systemic` | 원인 모를 발열·체중 감소가 동반되나요? |
| `rf_chest` | 운동 중 가슴 통증·심한 호흡곤란·어지럼이 있었나요? |
| `rf_pregnancy` | 임신 중이거나 출산 직후인가요? |
| `rf_doctor_stop` | 의료진에게 운동 제한을 안내받았나요? |

### 6.4 STAGE 2 — 운동 설문
| ID | 문항 | 타입 | 비고 |
|---|---|---|---|
| `body_parts` | 불편한 부위 | multi(최대 3) | 어깨/허리/무릎/발목/목·등상부/없음 |
| `pain_level_{part}` | 부위별 통증 강도 | 0~10 슬라이더 | 0=없음, 10=가장 심함 |
| `pain_duration_{part}` | 지속 기간 | single | 3일 이내 / 1~4주 / 1~3개월 / 3개월 이상 |
| `pain_trigger_{part}` | 언제 아픈가 | multi | 움직일 때/앉아 있을 때/아침에/운동 후/항상 |
| `activity_freq` | 주당 운동 빈도 | single | 0회 / 1-2회 / 3-4회 / 5회 이상 |
| `experience` | 운동 경험 | single | 처음 / 조금 / 익숙함 |
| `time_budget` | 하루 가능 시간 | single | 5분 / 10분 / 15분 / 20분+ |
| `equipment` | 가능한 장비 | multi | 없음/밴드/매트/덤벨/철봉 |
| `goal` | 목표 | multi(최대 2) | 회복 / 체형교정 / 기능향상 / 체중관리 / 근육량 |

### 6.5 STAGE 3 — 영양 설문
| ID | 문항 | 타입 | 학생 모드 |
|---|---|---|---|
| `meal_regularity` | 하루 몇 끼를 규칙적으로 먹나요 | single | 노출 |
| `protein_freq` | 단백질 식품(고기·생선·달걀·두부·유제품) 섭취 빈도 | single | 노출 |
| `veg_freq` | 채소·과일 섭취 빈도 | single | 노출 |
| `water` | 수분 섭취 | single | 노출 |
| `nutrition_goal` | 영양 목표 | single | **학생 모드: "체중 감량" 선택지 제거, "건강한 성장·컨디션" 로 대체** |
| `restriction` | 알레르기·식이 제한 | multi | 노출 |
| `late_night` | 야식·결식 습관 | single | 노출 |

> **금지 문항**: 목표 체중, 감량 희망 kg, 감량 기한, 체지방률 목표.
> 사유: 성장기 청소년 섭식장애 위험. SAFETY_POLICY.md §6 참조.

## 7. 운동 추천 로직 (요약)

> 전체 규칙과 의사코드는 ARCHITECTURE.md §6 참조. 여기서는 정책 수준만 기술한다.

### 7.1 3단계 파이프라인
```
[1] 차단 판정   레드 플래그 → 루틴 미제공
       ↓
[2] 카테고리 선택   부위 + 목표 → 운동 카테고리 결정
       ↓
[3] Phase 결정   통증 강도 + 지속 기간 + 경험 → Phase 1~4 중 시작점 결정
       ↓
[4] 루틴 조립   카테고리 × Phase × 시간예산 × 장비 → 동작 목록
```

### 7.2 카테고리 매핑 원칙
| 입력 | 추천 카테고리 |
|---|---|
| 어깨 통증 | 어깨 회복운동 (+ 동적웜업) |
| 허리 통증 | 허리 회복운동 (+ 체형교정) |
| 무릎 통증 | 무릎 회복운동 |
| 발목 통증 | 발목 회복운동 |
| 목·등 상부 | 목/등 상부 회복운동 (+ 체형교정) |
| 통증 없음 + 기능향상 | 기능성 운동 + 동적웜업 |
| 통증 없음 + 체형교정 | 체형교정 + 기능성 운동 |

### 7.3 Phase 결정 원칙 (설계 초안 — 전문가 검수 필요)
| 조건 | 시작 Phase |
|---|---|
| 통증 7 이상 | **루틴 미제공 → 상담 안내** |
| 통증 4~6 | Phase 1 (통증 완화 / 가동성) |
| 통증 1~3, 지속 4주 이상 | Phase 2 (안정화 / 활성화) |
| 통증 0~1, 최근 회복 | Phase 3 (근력 회복) |
| 통증 0, 재발 예방 목적 | Phase 4 (기능 복귀 / 예방) |

> 위 컷오프 숫자(7 / 4~6 / 1~3)는 **설계 초안값**이다. 임상 근거 기반 확정 전이며,
> 건강운동관리사·물리치료사·재활의학과 전문가 검수 후 확정한다. CONTENT_GUIDE.md §8 검수 체크리스트 참조.

### 7.4 진행(Progression) 원칙
- Phase 상승 조건: 해당 Phase 최소 수행 횟수 충족 **AND** 운동 후 통증 증가 보고 없음.
- Phase 하강 조건: 운동 후 통증 증가 2회 연속 보고 → 한 단계 하향 + 안내.
- 3회 연속 통증 증가 → 루틴 중단 + 상담 안내.
- 자동 Phase 상승은 하지 않는다. **항상 사용자 확인 후 상승.**

## 8. 영양 추천 로직 (요약)

### 8.1 4개 트랙
| 트랙 | 대상 | 핵심 메시지 |
|---|---|---|
| 다이어트 / 건강 체중관리 | 성인 전용 | 극단 제한 없이 식사 질 개선 |
| 벌크업 / 근육량 증가 | 성인 + 학생(성장 고려) | 끼니당 단백질 확보, 총식사량 충분히 |
| 일반 건강식 | 전체 | 균형·규칙성 |
| 회복 / 면역 / 미네랄 | 부상·회복기 | 단백질 + 채소·과일 + 수분 |

### 8.2 표시 방식 — 모드별 분기 (핵심 정책)
| | 학생 모드 | 일반 모드 |
|---|---|---|
| 칼로리 숫자 | **표시하지 않음** | 참고 범위로 표시 가능 |
| 다량영양소 | 비율 개념만 설명 | 비율(%) 표시 |
| 1회 섭취량 | **손바닥·주먹·엄지 기준** | 손 기준 + 그램 병기 |
| 체중 목표 | **기능 없음** | 기능 없음 (1차 MVP 공통 제외) |
| 감량 트랙 | **선택 불가** | 선택 가능 |

**손 기준 가이드 (전 모드 공통 표기법)**
- 단백질: 손바닥 크기 1개분
- 채소: 주먹 1~2개분
- 탄수화물: 주먹 1개분
- 지방: 엄지 1개분

> 다량영양소 비율 수치는 목표별로 다르게 제시할 예정이나, **구체 비율값은 확정하지 않았다.**
> 한국인 영양소 섭취기준 최신판 및 영양 전문가 검수 후 `content/nutrition/*.json` 에 반영한다.

### 8.3 영양 안전 규칙
- 보충제 브랜드·제품 추천 금지.
- 특정 질환 식이요법(신장질환 저단백식 등) 제공 금지 → 전문가 안내.
- 결식 유도 금지. 단식·원푸드·디톡스 콘텐츠 금지.
- 학생 모드에서 "체중", "감량", "칼로리" 단어를 결과 화면에 노출하지 않는다.

## 9. 위험 신호 처리 방식

### 9.1 3단계 게이트
```
게이트 A  설문 진입 시점   레드 플래그 스크리닝 → 차단
게이트 B  루틴 생성 시점   통증 강도 컷오프 → 차단 또는 Phase 하향
게이트 C  운동 중/후       중단 사유·통증 증가 → 하향 또는 차단
```

### 9.2 차단 시 사용자에게 제공하는 것
1. 왜 루틴을 제공하지 않는지 설명 (진단명 없이, 사유 유형만)
2. 어디에 상담해야 하는지 (정형외과·재활의학과·스포츠의학, 학생은 보건교사·보호자)
3. 응급 상황 안내 (가슴 통증·호흡곤란·의식저하 → 119)
4. "상태가 나아지면 다시 설문할 수 있다"는 재진입 경로

### 9.3 차단 시 제공하지 않는 것
- 대체 운동 루틴 (우회 제공 금지)
- "가벼운 스트레칭만 하세요" 같은 개별 조언
- 병명 추정, 원인 설명

## 13. UI/UX 디자인 방향

### 13.1 톤 & 무드
- 키워드: **신뢰 · 차분 · 코칭**
- 병원 느낌(차갑고 임상적)도, 피트니스 앱 느낌(자극적·경쟁적)도 아닌 중간.
- "옆에서 지켜봐 주는 체육 선생님" 어투: 존댓말, 짧은 문장, 명령형 대신 권유형.

### 13.2 컬러 방향 (초안)
| 역할 | 방향 |
|---|---|
| Primary | 딥 그린-틸 계열 (회복·안정) |
| Secondary | 소프트 블루 |
| Warning | 앰버 — 주의 안내용 |
| Danger | 레드 — 중단·상담 안내 전용 (남용 금지) |
| Surface | 오프화이트 / 다크모드 대응 |

### 13.3 타이포
- 본문 16sp 이상, 실행 화면 동작명 24sp 이상 (팔 뻗은 거리에서 읽혀야 함)
- 한글 가독성 우선 폰트, 숫자 혼용 시 정렬 유지

### 13.4 인터랙션 원칙
1. **한 화면 한 질문** — 설문은 스크롤 나열이 아니라 단계 진행.
2. **되돌아가기 항상 가능** — 설문 중 이전 답 수정 허용.
3. **운동 중 화면은 손이 바쁜 상태 기준** — 큰 버튼, 자동 진행 + 수동 제어 병행.
4. **위험 안내는 회피 불가** — 스킵 버튼 없음, 스크롤 끝까지.
5. **숫자보다 상태 언어** — "통증 6" 대신 "움직일 때 꽤 아픔" 라벨 병기.
6. 접근성: 대비 4.5:1 이상, 터치 타깃 48dp 이상, 스크린리더 라벨 필수.

### 13.5 화면 하단 고정 문구 (결과·루틴 화면 상시)
> "이 앱은 의학적 진단이나 치료를 제공하지 않습니다. 통증이 심해지면 즉시 중단하고 전문가와 상담하세요."

## 15. 성공 지표 (초안)
| 지표 | 정의 | 목표 방향 |
|---|---|---|
| 설문 완주율 | 설문 시작 → 결과 도달 | 높을수록 좋음 |
| 첫 루틴 완료율 | 결과 도달 → 루틴 1회 완료 | 높을수록 좋음 |
| 통증 증가 보고율 | 운동 후 "통증 증가" 비율 | **낮을수록 좋음 — 최우선 안전 지표** |
| 상담 안내 이탈 | 차단 화면 도달 후 재진입 | 관찰 지표 |
| 7일 재방문 | | 높을수록 좋음 |

> 지표 수집도 **로컬 집계만** 한다. 서버 전송 시점에는 개인정보 처리방침·동의 절차를 새로 설계한다.
